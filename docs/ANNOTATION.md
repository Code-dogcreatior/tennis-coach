# 真实场景评测集：标注说明

目的：在接近实际使用的视频（真实球场、业余球员、手机/固定机位）上，直接测出系统的

* 挥拍检出率（标注的挥拍有多少被找到，系统找到的挥拍有多少是真的）；
* 动作识别（正手 / 单反 / 双反 / 发球，以及高压、截击这类非目标动作是否被拒识）；
* 击球时刻误差（系统估计的击球时刻 − 标注的击球帧）；
* 持拍手、机位判断。

技术动作的对错（抛球手、击球点高度……）**不在这里标**：这需要教练判断，否则等于用同样的 2D 观察检验自己。

## 1. 准备视频

**公开的评测片段**（8 段 CC BY YouTube 视频，清单在 `data/labels/eval_real_manifest.csv`）：

```bash
uv run python scripts/fetch_eval_real.py
```

**自己的视频**（例如发球动作库）：先转换成“恒定帧率、首帧在 0 秒、无音频”的 MP4，再放进 `data/raw/annotate/`：

```bash
uv run python scripts/prep_annotate.py 我的视频/*.mov
```

为什么必须转换：标注工具按时间定位帧（第 n 帧 = [n/fps, (n+1)/fps)）。YouTube 截取的片段常常从第 1 帧的时间开始，手机视频常常是可变帧率，这两种情况都会让标注的击球帧和系统分析的帧对不上。工具打开未转换的视频时会显示红色警告。

视频本身不进 git（`data/raw/` 被忽略），只有标注 JSON 进 git。

## 2. 标注

启动应用（`uv run tennis-coach`），打开 `/annotate.html`（页面顶部“标注”）。

1. 左上角填写**标注人**（字母/数字，例如自己的名字缩写）。不同标注人的结果分开保存，可以算一致率。
2. 选一个视频。快捷键：

   | 按键 | 作用 |
   |---|---|
   | 空格 | 播放 / 暂停 |
   | ← / → | 后退 / 前进 1 帧 |
   | Shift + ← / → | 后退 / 前进 10 帧 |
   | F / B / D / S / M / V / O | 在当前帧标一次：正手 / 单手反手 / 双手反手 / 发球 / 高压 / 截击 / 其他 |
   | U | 切换选中那条的“不确定” |
   | Delete | 删除选中那条 |
   | Ctrl + S | 立即保存（平时改动后 0.8 秒自动保存） |

3. 规则：
   * 只标**主要球员**（离镜头最近、画面最完整的那个人）的每一次完整挥拍，失误球也标；其他人不标。
   * **击球帧** = 球第一次碰到拍面的那一帧。球看不清时，发球取“拍头指向正上方、手臂完全伸直的最后一帧”，底线球取拍面到达击球位置的那一帧，并勾“不确定”。
   * 空挥照样标，备注“空挥”；抛球后没击球不标；视频开头/结尾被截断、看不到击球的挥拍不标。
   * 切削反手按单/双手归类，备注“切削”。
   * 当前帧 ±3 帧内已有一条时，再按快捷键会改它的动作类型，不会新建。
4. 填写视频级信息：机位、持拍手、水平。整段都检查完后把状态改成**已完成**——评测只用已完成的视频。

标注保存在 `data/labels/annotations/<视频>.json`，一个视频一个文件，里面每个标注人一块。

## 3. 评测

```bash
uv run python scripts/eval_real.py [--annotator 你的名字]
```

结果写到 `reports/eval_real.md` / `.json`：检出率、混淆矩阵、击球时刻误差（毫秒和帧）、持拍手；同一视频有两个标注人时，还会给出两人的一致率。

## 4. 提交

```bash
git add data/labels/annotations data/labels/eval_real_manifest.csv
git commit -m "标注：..."
git push
```
